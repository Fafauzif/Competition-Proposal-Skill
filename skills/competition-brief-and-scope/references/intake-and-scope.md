# Intake and Scope Examples

A private working note can use these six fields when the task needs continuity:

| Field | Record |
|---|---|
| Decision | Decision-maker, problem and intended outcome |
| Required output | Artifact, audience, language, round and required components |
| Official rules | Current rule, exact source and interpretation |
| Scope and depth | Required decisions/analysis inside each component, constraints and protected material |
| Evidence | Inputs available now, crucial gaps and what a gap changes |
| Handoff | Decisions made, remaining material questions and completion evidence |

## Route by the question

- A client gives teams a customer retention case and asks for a written recommendation with implementation. Lead with the client decision and root causes, then bring in commercial modeling where it changes the recommendation.
- An organizer asks teams to create a venture and substantiate buyer demand, use of funds and margins. Route to the business-plan skill even if the packet uses “case” or calls the event an essay round.
- A technical innovation brief asks for a literature-led problem, mechanism and implementation. Route to the innovation-essay skill. A Gantt and cost estimate can support feasibility when useful without turning the entry into an investor pitch.
- For mixed requirements, follow the actual rubric and submission format. If the difference changes whether finance dominates the argument, ask which decision the judges are supposed to make or check the organizer's clarification.

## Protect the author's work

If a comment marks one paragraph as robotic, inspect the rest for recurring problems. Correct the marked paragraph and ask before changing unmarked prose. If the user authorizes a whole-essay voice pass, the scope changes to the whole essay. Preserve its evidence, argument, accepted formatting and citation targets while revising that language.

If a six-page maximum includes four appendix pages by explicit instruction, preserve that allocation unless the user changes it. If the user subsequently asks that appendix starts share pages where possible and the hard rule is a maximum, reflow complete exhibits and report the actual page count. Keep visuals readable and retain all requested exhibit roles. Use the additional space only when it improves the clarity or evidence of the submission.

## Check before release

For each requested component, locate its rendered equivalent and test where possible. Confirm a causal diagnosis still explains the cause, a solution still explains the operating mechanism, and an implementation section still gives its owners and dependencies. A short task should surface only the unresolved question relevant to that task.
