## Acceptance checks for the bank

- Give the entry point a short innovation-essay brief with an idea already selected. It should build on that idea and reserve alternatives for a substantive weakness. An English technical example and an Indonesian essay example should lead to different prose decisions.
- Give the entry point a request to revise one marked passage. The result should repair that passage and preserve the rest of the work until the user authorizes broader changes.
- Provide a BPC brief with a written proposal due. The workflow should cover customer, payer, delivery, unit economics, funding, and risks in the appropriate written format. The title system should serve navigation.
- Provide a BCC brief that requests a written recommendation, then a separate request for an editable deck. Only the second request should activate the deck-specific workflow. Either can use a causal issue tree if the diagnosis needs one.
- Force the chart workflow into an environment without TikZ/PGFPlots. A supported fallback should carry the same series, units, labels, and semantics into a readable result. Record backend identity in the working notes.
- Give the reviewer a figure with a plausible-looking but unsupported number and a body sentence linked to the wrong section on the right page. A meaningful review should flag both.
